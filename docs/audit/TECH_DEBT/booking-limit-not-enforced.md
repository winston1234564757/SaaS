# [TECH_DEBT] Booking Limit — Розсинхрон 30 vs 50 між BOOKIT.md і кодом

## Статус
🟡 **МІНОРНИЙ БОРГ — Розсинхрон документації, не код**

## Факти

**Реальний ліміт в коді = 30** (підтверджено в `createBooking.ts` рядок 186):
```typescript
if ((count ?? 0) >= 30) {
  return { error: 'Досягнуто ліміт 30 записів на місяць. Перейдіть на Pro.' };
}
```

| Джерело | Значення |
|---|---|
| `createBooking.ts` — реальний код | ✅ **30** |
| `LandingPricing.tsx` | ✅ **30** |
| `SupportPage.tsx` | ✅ **30** |
| `BOOKIT.md` | ❌ **50** ← розсинхрон |

## Проблема

`BOOKIT.md` містить застарілу інформацію: `50 записів/місяць`. Це дезорієнтує в процесі розробки.

## Відкрите питання (бізнес-рішення)

Вітос прокоментував: **"хз треба глибокий бізнес-аналіз"**

Варіанти для аналізу:
- **30** — низький поріг → швидша конверсія в Pro, але може відлякати нових майстрів
- **50** — вищий поріг → більше часу для user activation, але менша конверсія
- **Unlimited** на Starter + обмеження по фічах (Premium-only features) → альтернативна моетизаційна стратегія

## Рекомендація

До прийняття бізнес-рішення — просто оновити `BOOKIT.md`:
```
Starter | 0₴ | 30 записів/місяць  ← (було 50, виправлено)
```
