Dashboard is the battlefield for developing 3 fully independent design systems.

**Why:** Themes are NOT color swaps — each must deliver a unique UX, feel, and interaction personality. When a user switches theme, the product should feel like a different tool, not just look different.

**Process:**
1. Dashboard → test → make mistakes → correct → perfect
2. Lock in 3 complete, ideal design systems
3. Apply each theme to the full project — slowly, step by step, quality-first

**How to apply:**
- Never rush widget decisions — every layout/motion choice is defining a design system
- QA-gate with user before and after every widget
- No "quick fixes" — if something is wrong, fix it properly
- Mistakes on dashboard = learning. Mistakes after rollout to full project = costly regressions
- Each theme must have unique: layout hierarchy, information density, motion personality, interaction feel

**Three identities (not skins):**
- Blossom: Editorial / Kinfolk / light taupe — calm, content-first, typographic
- Studio: Architectural / Monocle / dark teal — dense, data-as-typography, tight
- Frost: Precision bento / lavender near-black — data-forward, grid-driven, clinical
