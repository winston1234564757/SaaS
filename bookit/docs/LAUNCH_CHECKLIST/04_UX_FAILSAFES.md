# 04 — UX Failsafes Checklist

Аналіз обробки критичних помилок, "порожніх станів" та якості інтерфейсних текстів.

---

### 1. Обробка помилок (Error Boundaries)

| Пункт | Статус | Докази / Коментар |
|---|---|---|
| **Root Error Boundary** | [✅ PASS] | `src/app/error.tsx` присутній, має UI з кнопкою "Оновити". |
| **Global Error (Layout)** | [❌ FAIL] | **ВІДСУТНІЙ:** `global-error.tsx` у корені `app/` не знайдено. Помилки всередині `layout.tsx` (напр. збій Auth Provider) призведуть до "білого екрану". |
| **Dashboard Isolation** | [✅ PASS] | `app/(master)/dashboard/error.tsx` ізолює помилки дашборду від решти додатку. |

### 2. Server Actions Errors

| Пункт | Статус | Докази / Коментар |
|---|---|---|
| **Безпечні повідомлення** | [✅ PASS] | Більшість екшенів використовують `parseError(err)` з `src/lib/utils/errors.ts`. Це приховує сирі SQL-помилки від юзера. |
| **Zod Error Mapping** | [✅ PASS] | Схема `createBooking` має кастомні повідомлення українською ("Невірний формат дати" тощо). |
| **Empty States** | [⚠️ MANUAL CHECK] | Перевірте `bookings/page.tsx`, чи є там заглушка "У вас ще немає записів" (рекомендовано UX стандартами). |

### 3. Локалізація та Контент

| Пункт | Статус | Докази / Коментар |
|---|---|---|
| **Плюралізація** | [✅ PASS] | Використовується `pluralUk(n, 'послуга', 'послуги', 'послуг')`. Прямих тернарників `count === 1 ? ...` не знайдено. |
| **Hardcoded English** | [✅ PASS] | Масових `Lorem Ipsum` не виявлено. Весь UI перекладено українською. |
| **Identity Display** | [✅ PASS] | Коректно використовується пріоритет `business_name` → `full_name`. |

---

> [!TIP]
> **Порада:** Створіть `src/app/global-error.tsx` для обробки найбільш критичних збоїв на рівні кореневого layout.
