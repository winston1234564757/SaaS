# 02 — B2C Client Flow Checklist

Аналіз шляху клієнта: від вибору послуги до підтвердження запису та захисту від технічних збоїв.

---

### 1. Захист від овербукінгу (Race Conditions)

| Пункт | Статус | Докази / Коментар |
|---|---|---|
| **Атомарність слотів** | [✅ PASS] | Міграція `091_booking_slot_unique.sql` створює `UNIQUE INDEX booking_slot_collision`. Це гарантує на рівні БД, що два записи на один час неможливі. |
| **Обробка конфліктів** | [✅ PASS] | `createBooking.ts` (рядок 524) перевіряє помилку `23505` та повертає зрозуміле повідомлення: "Цей час вже заброньований". |
| **Stock Management** | [✅ PASS] | Товари списуються через атомарний `update ... gte('stock_qty', cp.quantity)`. Це запобігає "продажу в мінус". |

### 2. Таймзони та Дати

| Пункт | Статус | Докази / Коментар |
|---|---|---|
| **Серверна обробка** | [✅ PASS] | Використовується `toZonedTime` з `date-fns-tz`. |
| **Таймзона майстра** | [✅ PASS] | `createBooking` витягує `mp.timezone` (fallback `Europe/Kyiv`). Це важливо для майстрів за кордоном. |
| **Збереження у БД** | [✅ PASS] | Дати зберігаються як `date` (ISO string), час як `time without time zone`. Це стандарт для Supabase, що уникає зсуву годин при SSR. |

### 3. Валідація та Безпека (Server Actions)

| Пункт | Статус | Докази / Коментар |
|---|---|---|
| **Архівні послуги** | [❌ FAIL] | **КРИТИЧНО:** `createBooking.ts` (рядок 198) НЕ фільтрує послуги за `is_archived: false`. Клієнт теоретично може забронювати видалену послугу, якщо знає її ID. |
| **Подвійний сабміт** | [✅ PASS] | `BookingWizard.tsx` має стейт `saving` та guard `if (saving) return`. Кнопка сабміту деактивується. |
| **Валідація ціни** | [✅ PASS] | Сервер ПОВНІСТЮ ігнорує ціну з клієнта та перераховує її заново на основі БД (`canonicalServices`). Клієнт не може підмінити ціну у DevTools. |

---

> [!CAUTION]
> **ТЕРМІНОВО:** Потрібно додати `.eq('is_archived', false)` у запити до таблиць `services` та `products` всередині `createBooking.ts`.
