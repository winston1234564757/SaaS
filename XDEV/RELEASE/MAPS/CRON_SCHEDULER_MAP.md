# ⏰ Cron Scheduler & Background System Map — BookIT

Цей документ визначає розклад, структуру та логіку фонових завдань (Cron Jobs), що керують нагадуваннями про записи, аналітикою утримання (retention) та білінговими процесами підписок.

---

## 🔒 Захист Кронів

Усі фонові маршрути розташовані в директорії `bookit/src/app/api/cron/`. Вони захищені заголовком `Authorization: Bearer {CRON_SECRET}`. У разі його відсутності або невідповідності повертається помилка `401 Unauthorized`.

---

## 📅 Реєстр Фонових Завдань (Cron Registry)

Наші крони налаштовані на виконання через Vercel Cron Jobs або зовнішній планувальник (наприклад, Supabase pg_cron / GitHub Actions).

| Маршрут (API Route) | Розклад (Cron Expr) | Цільовий функціонал | Основні дії та логіка |
|---|---|---|---|
| `/api/cron/reminders` | `0 * * * *` (щогодини) | Нагадування клієнтам та майстрам | 1. Розрахунок трьох вікон нагадувань (24 год, 2 год, 30 хв).<br>2. Розсилка сповіщень через `NotificationOrchestrator`. SMS надсилається лише на вікні 2h (critical).<br>3. О 08:00 за київським часом надсилає майстрам ранковий брифінг записів на сьогодні. |
| `/api/cron/rebooking` | `0 10 * * *` (щодня о 10:00) | Утримання клієнтів (Retention) | 1. Запуск RPC `get_rebooking_due_clients`. Знаходить клієнтів, у яких настав час повторного візиту (залежно від `retention_cycle_days` майстра).<br>2. Відправка персоналізованого Push/Telegram сповіщення про запис.<br>3. Запобігання дублюванню через перевірку унікальності в `rebooking_reminders`. |
| `/api/cron/reset-monthly` | `5 0 1 * *` (1-го числа щомісяця о 00:05) | Пониження тарифів підписки | 1. Перевірка терміну дії підписки майстра (`master_subscriptions`).<br>2. Якщо оплата прострочена, тариф переводиться на Free (Starter).<br>3. Надсилання майструBillingAlert через `notifyMasterBilling`. |
| `/api/cron/expire-subscriptions` | `0 2 * * *` (щодня о 02:00) | Автоматичні рекурентні списання | 1. Вибірка підписок з наближенням дати оплати.<br>2. Спроба списання суми з токена збереженої картки через Monobank Merchant API (recurring payment).<br>3. При відхиленні платежу — ініціація Dunning-періоду (повторні спроби 3 дні + сповіщення `subscription_failed`). |
| `/api/cron/check-uncompleted` | `*/15 * * * *` (кожні 15 хвилин) | Очищення незавершених записів | 1. Пошук записів, які не були підтверджені протягом ліміту часу (Buffer Minutes).<br>2. Перевірка ідемпотентності (захист від повторних перевірок одного запису).<br>3. Автоматичне скасування запису та вивільнення слотів у календарі. |

## 📊 Notification Cascade у Нагадуваннях (`/reminders`)

Нагадування надсилаються суворо за каскадним принципом для оптимізації витрат на SMS:

```
                  [Настало вікно нагадування]
                               |
                   Яке вікно нагадування?
                     /               \
              [24 години / 30 хв]   [2 години (Критичне)]
                    /                 \
        In-App + Push (Паралельно)    In-App + Push (Паралельно)
                   |                             |
         Клієнт прочитав або             Клієнт прочитав?
         має активний TG?                 /             \
            /         \                 Так            Ні
          Так          Ні                |              |
           |            |             Успішно     Telegram-повідомлення
        Успішно    Telegram-повідом.                    |
                                                   TG доставлено?
                                                    /         \
                                                  Так          Ні
                                                   |            |
                                                Успішно     TurboSMS (SMS fallback)
```

### SMS Guard
Для уникнення випадкових витрат на SMS, події нагадувань 24h та 30m мають у конфігурації `notifMap.ts` параметр `sms: null`. Навіть якщо відправка в інші канали зазнає невдачі, SMS-провайдер для них **фізично не буде викликаний**. SMS дозволено лише для події `reminder_2h` (як остання лінія зв'язку).
