# Product Whitepaper — BookIT Ecosystem & Tech Stack

> **Технічна специфікація та архітектурні рішення**
> **Версія:** 8.2 | **Дата:** Травень 2026 | **Статус:** Production Ready

---

## 1. Introduction & Vision

**BookIT** — це інтелектуальна операційна система для незалежних б'юті-професіоналів. Основна мета продукту — перетворити персональну веб-сторінку майстра на повністю автономну систему залучення клієнтів, обробки записів, логістики товарів та фінансового обліку. 

Цей документ містить детальний опис технічної архітектури, структури бази даних, алгоритмів Smart Slot Engine, системи динамічного ціноутворення та каскадної системи сповіщень.

---

## 2. Core Technology Stack

BookIT побудований на базі сучасного, надшвидкого та масштабованого стеку технологій, що забезпечує швидкість завантаження сторінки `<1.2с` та підтримку PWA:

* **Frontend**: Next.js 16 (App Router) + React 19 із увімкненим React Compiler (автоматична мемоізація компонентів, що запобігає зайвим рендерам).
* **Styling**: Tailwind CSS v4. Компоненти використовують HSL-палітри з унікальними темами (Blossom, Studio, Frost).
* **State Management**: TanStack Query v5 (серверний стан) + Zustand v5 (локальний клієнтський стан UI).
* **Database & Auth**: Supabase (PostgreSQL 16) + Row-Level Security (RLS) + Realtime Sync (через WebSockets).
* **Infrastructure**: Vercel Edge Network (Edge Runtime для API-роутів та географічно розподілений CDN).
* **Payments**: Monobank acquiring (Ed25519-верифікація сигнатур для безпеки рекурентних платежів).
* **Ambient Background System**: Реалізовано на рівні CSS-анімацій (3D ambient blobs, vignette, film grain) без використання важких JS-бібліотек, що забезпечує 60 FPS навіть на слабких мобільних пристроях.

## 3. Database Architecture & Schema Scaling

База даних містить **140+ SQL-міграцій**, що забезпечують безперебійне оновлення схеми без деградації продуктивності.

### Ключові оптимізації в PostgreSQL

1. **O(1) Recalculation of Ratings (міграція 039)**:
   Замість важкого сканування `AVG()` по всій таблиці відгуків при кожному запиті, рейтинг майстра перераховується інкрементно при додаванні нового відгуку:
   ```sql
   UPDATE master_profiles
   SET rating = (rating * rating_count + new_rating) / (rating_count + 1),
       rating_count = rating_count + 1
   WHERE id = master_id;
   ```

2. **JSONB для гнучких конфігурацій**:
   Права ціноутворення (`pricing_rules`) та робочі години (`working_hours`) зберігаються у форматі `JSONB` на таблиці `master_profiles`. Це дозволяє оновлювати логіку без проведення деструктивних міграцій типу `ALTER TABLE`.

3. **Часткові індекси (Partial Indexes)**:
   Індекси будуються тільки для релевантних рядків, зменшуючи розмір індексів на диску:
   ```sql
   CREATE INDEX idx_bookings_next_visit
     ON bookings(master_id, next_visit_suggestion)
     WHERE next_visit_suggestion IS NOT NULL;
   ```

4. **Ключові RPC-функції**:
   * `get_master_clients`: повертає CRM-дані клієнтів, їхній статус повернення (retention status), суму витрат та медичні нотатки. Агрегація відбувається повністю на стороні сервера.
   * `check_and_log_sms_attempt`: атомарна транзакція з advisory lock (`pg_try_advisory_xact_lock`) для захисту від паралельних запитів (race conditions) при верифікації OTP.
   * `get_master_referral_history`: RPC-функція для миттєвого отримання реферального графу без затримок (waterfalls) на фронтенді.

## 4. Slot Engine & Dynamic Pricing

### 4.1 Smart Slot Engine
Алгоритм `generateAvailableSlots()` (`src/lib/utils/smartSlots.ts`) генерує сітку доступного часу на основі шаблону робочого дня майстра, відпусток (`master_time_off`) та існуючих записів. 

Слоти класифікуються за 6 типами стану:
- `available` — вільний для запису.
- `booked` — перетинається з існуючим записом.
- `break` — час обіду або перерви.
- `buffer` — технічна пауза між клієнтами (наприклад, 15 хв на прибирання робочого місця).
- `overflow` — час виходить за межі робочого дня.
- `past` — минулий час з урахуванням 30-хвилинного safety-буфера.

Алгоритм підтримує **multi-service** запис: якщо клієнт обирає кілька послуг, система шукає consecutive (послідовний) блок часу відповідної сумарної тривалості.

### 4.2 Dynamic Pricing Engine
Модуль динамічного ціноутворення (`src/lib/utils/dynamicPricing.ts`) автоматично коригує вартість послуги в копійках (цілі числа в БД) на основі 4 правил:
1. **Peak Hours**: Націнка до `+50%` (наприклад, п'ятниця-субота з 16:00 до 20:00).
2. **Quiet Hours**: Знижка до `-30%` (наприклад, понеділок-середа з 09:00 до 12:00).
3. **Early Bird**: Знижка до `-10%` за завчасне бронювання (більше ніж за 14 днів).
4. **Last Minute**: Знижка до `-20%` за термінове бронювання (менше ніж за 4 години до слоту).

*Захист*: Early Bird та Last Minute є взаємовиключними на рівні валідації Zod. Нижня межа знижки жорстко обмежена на рівні `-30%` (`DISCOUNT_FLOOR`), а верхня накрутка — `+50%` (`MARKUP_CEIL`).

## 5. Notification Cascade v7.0

Для забезпечення 98% доставки сповіщень та мінімізації витрат на SMS BookIT використовує `NotificationOrchestrator` з 3-рівневим каскадом:

```
                  [Подія сповіщення]
                          │
                          ▼
            [In-App + Web Push (VAPID)] (Паралельно)
                          │
                  ┌───────┴───────┐
             (Доставлено?)     (Ні / Немає підписки)
                  │               │
                  ▼               ▼
              [Успішно]      [Telegram Bot] (через telegram_chat_id)
                                  │
                          ┌───────┴───────┐
                     (Доставлено?)     (Ні / Не підключено)
                          │               │
                          ▼               ▼
                      [Успішно]     [SMS (TurboSMS)] (Тільки для critical)
```

### SMS Guard (`sms: null`)
Усі 21 тип подій зареєстровані в `src/lib/notifications/constants/notifMap.ts`. Тільки критичні події (`booking_created`, `booking_confirmed`, `booking_cancelled`, `reminder_2h`, `subscription_failed`) мають доступ до SMS-шлюзу. Для некритичних подій SMS заблоковано на рівні коду за допомогою `sms: null` обмежувача, що запобігає фінансовим втратам через зайві SMS.

### Логування та аналітика
Всі відправки логуються в таблицю `notification_logs` із фіксацією статусу (`success/failed/skipped`) та коду помилки для аудиту якості доставки.

## 6. Security & Rate-Limiting

1. **Magiclink OTP (Passwordless Auth)**:
   При авторизації паролі не використовуються. Клієнт вводить номер телефону, отримує SMS OTP, після перевірки якого сервер генерує одноразовий `magiclink` токен. Це виключає ризик витоку бази паролів.
2. **Advisory Locks**:
   Для запобігання атакам типу SMS-flood (швидке повторне надсилання запитів) використовується advisory lock в PostgreSQL:
   ```sql
   SELECT pg_try_advisory_xact_lock(hashtext(phone_number))
   ```
3. **Rate Limits**:
   OTP-коди обмежені до 3 спроб за 15 хвилин для одного номера телефону та до 10 запитів за годину з однієї IP-адреси.

## 7. E-Commerce & Portfolio Consent System

### 7.1 Інтеграція з Новою Поштою
Майстер може активувати доставку товарів через кабінет (`master_profiles.ships_nova_poshta`). Під час оформлення замовлення (`createOrder` server action) клієнт обирає тип доставки (самовивіз або Нова Пошта), заповнює адресу, а система автоматично резервує товар на складі за допомогою RPC `increment_stock_rpc` (або декрементує його).

### 7.2 Система згоди клієнта на портфоліо (Portfolio Consent)
Для дотримання GDPR та конфіденційності клієнтів BookIT реалізує двофакторну публікацію робіт:
1. Майстер завантажує фото кейсу в портфоліо (через DND-uploader у приватний bucket `portfolios` зі шляхом `{master_id}/items/{item_id}/{file}`).
2. Майстер вказує клієнта зі своєї CRM-бази (`tagged_client_id`).
3. Робота створюється зі статусом `consent_status = 'pending'` і є **непублічною**.
4. Клієнт отримує сповіщення у кабінеті `/my/notifications` та може натиснути **Схвалити** (`approvePortfolioConsent`) або **Відхилити** (`declinePortfolioConsent`).
5. Тільки після схвалення статус змінюється на `approved`, а робота з'являється у публічній галереї майстра.
