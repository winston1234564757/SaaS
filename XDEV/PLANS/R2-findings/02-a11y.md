# R2 Accessibility Audit — 02-a11y

Date: 2026-07-07 · Launch: 2026-07-10
Scope: Shop (cart/checkout/NP picker), Orders dashboard, client cabinet /my/* (C-DESK-01), BookingWizard (5 steps), dynamic pricing UI, plus codebase-wide sweeps (div-onClick, button type, aria-label/pressed, aria-live, focus traps, touch targets, Lucide style rule, alt, contrast).
Mode: READ-ONLY. No project files edited. Every finding verified by reading the actual code.

## Headline
The codebase is far above average on button semantics — the div-onClick sweep (multiline, incl. `motion.*`) found only **3 live violations**, and priority surfaces (shop tiles, wizard slots, orders, /my/*, pricing) consistently use `<button type="button">` with `aria-label`/`aria-pressed`. The real gaps are **systemic, not local**: (1) the app has **zero `aria-live` regions and one `role="alert"` in the entire src** — toasts, booking confirmations, checkout errors and "saved" states are all silent for screen readers; (2) a family of **custom framer-motion drawers/modals bypasses the vaul/Radix `Sheet`** (including the launch-critical shop checkout) and ships with no dialog role, no focus trap, no Escape, no body scroll lock and a tabbable background; (3) the master wizard's `ClientCombobox` selects options on `onMouseDown` only, so **Enter cannot pick a client**.

### P1

`[P1] src/lib/toast/context.tsx:97-103` — Toast card is a `motion.div` with `onClick` (expands the collapsed stack). div-onClick = P1 by project rule, and this one is live on every surface in prod: keyboard users cannot expand the stack (lower toasts stay blurred/overlapped; their buttons are tab-reachable but visually illegible). Compounding: the toast container (`:182`) has **no `aria-live` / `role="status"`**, so every toast — including "запис підтверджено" style notifications — is completely silent for screen readers. Fix: container `role="status" aria-live="polite"`, expand-trigger → `<button type="button">` (or make the whole card a button with the action/close buttons outside it).

`[P1] src/components/master/dashboard/widgets/studio/MonthlyCalendarWidget.tsx:100-103` — Booking row is a `<div onClick={() => onOpen(b.id)} className="... cursor-pointer ...">`. Not focusable, not keyboard-operable, no role. Reachability note: Studio theme is `wip:true` (non-selectable in TechnicalIsland), so users can't hit it today — but it is shipped code and the rule is unconditional. Contrast: the **frost** twin (`widgets/frost/MonthlyCalendarWidget.tsx:94-97`) does this correctly with `<button type="button">`. Copy the frost pattern.

`[P1] src/components/master/dashboard/widgets/blossom/MonthlyCalendarWidget.tsx:122-124` — Same violation in the Blossom twin: booking row `<div ... cursor-pointer onClick={() => onOpen(b.id)}>`. Same wip-theme reachability note, same fix.

### P2

`[P2] src/components/public/shop/ShopCartBar.tsx:164-377 (pattern; 10+ surfaces)` — The **shop checkout drawer** (CartDrawer) is a hand-rolled framer-motion overlay: no `role="dialog"`/`aria-modal`, no focus trap (Tab walks the page behind it), focus is not moved into the drawer on open, **no Escape close** (grep: only DropdownMenu, PhotoLightbox and StepPreview handle Escape in all of src), and **no body scroll lock** (grep: only BentoBottomNav and OnboardingWizard lock `body.style.overflow`). Backdrop-click is the only pointer-free... pointer-only close. This also violates the project's own "drawers = vaul BottomSheet only" convention. Same pattern (verified each): `master/products/ProductFormDrawer.tsx:196-224`, `master/products/TransactionHistoryDrawer.tsx:46-83`, `master/portfolio/PortfolioItemEditor.tsx:167-172`, `master/dashboard/WidgetLibraryModal.tsx:31-35`, `master/bookings/dashboard/OpportunityMenu.tsx:19-23`, `public/NavLoginSheet.tsx:61-66`, `master/dashboard/SharePageCard.tsx:85-89` (QR), `shared/UpgradePromptModal.tsx:47-53`, `shared/BottomNav.tsx:95-100` (more-overlay). Checkout is launch-day money path — fix at least ShopCartBar by porting to `ui/Sheet` (Radix/vaul handle role, trap, Escape, lock — verified in `ui/Sheet.tsx`).

`[P2] src/components/shared/wizard/ClientCombobox.tsx:146` — Option buttons in the master-mode client picker use `onMouseDown={() => handleSelect(c)}` with **no onClick/onKeyDown**: pressing Enter on a focused option fires `click`, not `mousedown`, so **keyboard users cannot select an existing client** (workaround: type name+phone manually, losing CRM linkage/SafetyAlert). No arrow-key navigation either, despite otherwise exemplary combobox ARIA (`role="combobox"`, `aria-expanded`, `aria-controls`, `role="option"`). Keep `onMouseDown` for blur-race, add `onClick` fallback + ArrowDown/Up/Enter handling.

`[P2] src/components/public/shop/NovaPoshtaPicker.tsx:107-182` — Nova Poshta city/warehouse autocomplete (M-SHOP-05, new) has **none** of the combobox ARIA that ClientCombobox has: plain `<input>` with no `role="combobox"`, `aria-expanded`, `aria-controls` or `aria-autocomplete`; result dropdown is an unlabeled `<div>` of buttons; results appearing / "Відділень не знайдено" / loading are not announced; Escape does not close (outside-`mousedown` only, so Tab-out leaves the dropdown open). Options are real buttons so it is *operable* by Tab, but blind users get zero feedback that 15 cities appeared. Port the ClientCombobox ARIA.

`[P2] src/components/shared/BookingWizard.tsx:290-434` — No focus management between wizard steps: step containers unmount under `AnimatePresence` and the pressed "Далі" button disappears, dropping focus to `<body>`; nothing announces the new step (no aria-live, no focus to step heading). A keyboard/SR user completes step 1 and lands nowhere. `grep .focus(` in `shared/wizard/` = zero hits. Fix: on `go()`, move focus to the new step's heading (`tabIndex={-1}`) or announce via a polite live region fed by `WizardHero`.

`[P2] Async state changes are never announced (systemic — 1 role="alert" and 0 aria-live in all of src)` — Verified silent spots on money paths: `wizard/BookingSuccess.tsx:107` "Запис підтверджено" (step swap only, no `role="status"`, no focus move); `shop/ShopCartBar.tsx:355` checkout validation/server error `<p>`; `ShopCartBar.tsx:380-407` OrderSuccess full-screen replace; `wizard/ClientDetails.tsx:376-387` `saveError` block (incl. "slot already taken" which also silently yanks the user back to the datetime step); `master/pricing/DynamicPricingPage.tsx:476` "Збережено!" button-text swap. The only correct instance in the codebase is `ClientCombobox.tsx:130`. Minimum launch fix: `role="status"` on BookingSuccess/OrderSuccess containers, `role="alert"` on the two error blocks.

`[P2] src/components/shared/wizard/DateTimePicker.tsx:153-190, 270, 345-369` — Three rule violations in the redesigned datetime step: (a) date-strip day chips (`:153`) are toggles with no `aria-pressed` — selected day is color-only (slot chips at `:284` do it right); (b) slot chip `motion.button` (`:270`) is missing `type="button"` — the only wizard control without it; (c) master dynamic-price toggle (`:345`) is a visual switch with no `aria-pressed`/`role="switch"` — state is invisible to SR (the identical switch in `DynamicPricingPage.tsx:430-437` has `aria-pressed`, so the pattern exists).

`[P2] src/components/master/dashboard/widgets/frost/MonthlyCalendarWidget.tsx:38-77` — Frost (the **active** theme) calendar DayCell: correct `<button type="button">`, but selected state has no `aria-pressed` (project rule: calendar/heatmap cells are toggles), accessible name is the bare day number ("15" — no month/booking context), booking presence is conveyed only by 5px color dots + a **hover-only** tooltip (`:73` `hovered && ...` — never shown on focus), and cell height is `min-h-[32px]` (< 44px mobile floor). Add `aria-pressed`, an `aria-label` with date + booking count, and show the tooltip on focus.

`[P2] 15 live buttons missing type="button" (scripted scan, verified sample)` — Project rule: every `<button>` needs `type="button"`. Locations: `wizard/DateTimePicker.tsx:270` (slot chips — also above), `master/pricing/DynamicPricingPage.tsx:470` (SaveButton `motion.button` on priority surface 6), `master/pricing/PricingUpgradeGate.tsx:232,309`, `master/bookings/dashboard/MonthlyAnalyticsView.tsx:205,321`, `PeriodAnalyticsView.tsx:52`, `VerticalTimeline.tsx:596`, `master/dashboard/BentoGrid.tsx:152`, `QuickActions.tsx:105`, `master/settings/widgets/SegmentConfigWidget.tsx:56`, `shared/MobileHub.tsx:111`, `shared/support/SupportWidget.tsx:198`, `telegram/TelegramWelcome.tsx:305,320,418`. Mechanical one-pass fix.

`[P2] Touch targets below the project's own py-2 pill floor` — `public/ShopPage.tsx:148` category FilterChip `px-3.5 py-1.5` (~29px) on the mobile-first public shop; `master/products/ProductsPage.tsx:316` order-status filter pills `px-3 py-1.5`; `master/analytics/charts/RevenueLineChart.tsx:180,194` compare/export toolbar pills `py-1.5`. Rule: pills `py-2` minimum, 44px mobile. One class change each.

### P3

`[P3] src/components/master/dashboard/WeeklyOverview.tsx:111-119` — Chart-bar `<div onClick>` (would be P1) but the component is **dead code**: `WeeklyOverview` is never imported anywhere (grep — only the `useWeeklyOverview` hook is used, by the three `WeeklyChartWidget`s). Delete the file rather than fix it.

`[P3] Lucide icons receiving a style prop — 57 occurrences (scripted scan, verified sample)` — Direct violation of the project rule "Lucide: no style prop → wrap in `<span style={{color}}>`". Densest on priority surface 6: `master/pricing/PricingRuleStatsSheet.tsx:58,78,107,116,124`, `DynamicPricingPage.tsx:350,408`, `PricingUpgradeGate.tsx:67,115,211`; also `client/MyLoyaltyPage.tsx:291`, `public/PublicMasterPage.tsx:191,237,474`, `shared/MobileHub.tsx:126,293`, onboarding steps (×12), landing (×7), full list reproducible via scan. Convention/consistency issue, not a user-facing break — bulk cleanup task.

`[P3] Hover-only controls invisible on keyboard focus` — `shop/ShopCartBar.tsx:286,294` pickup-day slider arrows and `shop/ProductDetailView.tsx:96,104` gallery arrows use `opacity-0 group-hover:opacity-100` with no `focus-visible:opacity-100`: they ARE in the tab order, so keyboard focus lands on an invisible button (global `:focus-visible` outline draws around empty space). Add `focus-visible:opacity-100`.

`[P3] src/components/master/analytics/charts/RevenueLineChart.tsx:190-216` — Export dropdown: trigger has no `aria-expanded`, menu has no menu semantics, Escape doesn't close it, and dismissal is an invisible full-screen click-catcher `<div onClick>` (`:202`). Keyboard workaround exists (re-toggle the trigger), hence P3. The in-repo `ui/DropdownMenu.tsx` already handles Escape — reuse it.

`[P3] src/components/master/pricing/DynamicPricingPage.tsx:433` — All four rule toggles share the identical `aria-label="Увімкнути правило"` — a SR user tabbing the page hears four indistinguishable switches. Use `aria-label={'Увімкнути правило: ' + title}`.

`[P3] src/components/shared/wizard/ServiceSelector.tsx:225` — Carousel dot buttons labeled `aria-label={\`${i + 1}\`}` (just "1", "2"...). Say what it is: `Слайд ${i+1}`. Same file `:404` "Скинути" is a bare text button with no padding (sub-44px target, master-only surface).

`[P3] src/components/shared/wizard/BookingSuccess.tsx:145` — "Скопійовано!" copy-confirmation is a visual text swap only (no `role="status"`), same for the share fallback at `:73`. Part of the systemic live-region gap; listed separately because it's a one-attribute fix.

`[P3] Category badge contrast: white text on --cat-* tokens` — `public/ShopPage.tsx:111` and `shop/ProductDetailView.tsx:112` render 10-12px bold white text on `color-mix(87-93% cat-color)`. Computed: `--cat-other #A89F7C` ≈ 2.8:1, `--cat-nails #C2739A` ≈ 3.4:1 vs white — below the 4.5:1 requirement for small text, further diluted by the transparent mix over photos. Darken the mix or switch to dark-on-light chips.

`[P3] src/components/ui/Sheet.tsx:97-146` — `BottomVariant` (vaul) renders `Drawer.Title` but no `Drawer.Description`/`aria-describedby` (the Radix `DialogVariant` at `:83` does). Logs a Radix warning and SR users get no dialog description on every mobile sheet. One-line parity fix.
