1. **Легасі-хекси** на 4 правилах (`#D4935A` пік / `#789A99` тихий / `#5C9E7A` рання / `#C05B5B` остання) — борг Blossom-епохи у Frost-only світі. Той самий клас, що чистили в M-REV-01.

3. **Плаский список 4 карток без ієрархії** — надбавка і знижки в одному ряду, нуль семантики «заробити vs заповнити» (anti-ref PRODUCT: bento overuse).
4. **Нуль ціннісного обрамлення** для Pro — сухий хедер-форма, інструмент заробітку не відчувається.
5. **`PricingUpgradeGate` весь на тих самих хексах** (`#C05B5B/#D4935A/#5C9E7A/#789A99`) — для Starter домінує сторінку.

## Дизайн-напрям (APPROVED через brainstorming + craft + grill)

**Відчуття (founder QA 4/4):** авто-заробіток (ціни працюють самі) + доказ результату (цифра).
**Колір:** Restrained. База Frost slate `--primary` #0F172A. Семантика warm/cool: надбавка = `--warning` #B45309 (амбер, точково), знижки = `--success` #16803C (cool green). Розрізняє іконка + секція, не суцільний колір.
**Скоуп карток (founder: «1 і 3»):** рескін + живе прев'ю ціни **і** групування Знижки/Надбавки.

### Ієрархія (зверху вниз)
1. **Hero-смуга цінності** (Pro/Studio): serif-заголовок + підзаголовок автоматизації. **Доказ-цифра вбудована в рядок тексту, НЕ велике табло** (бан hero-metric). Показується лише коли `extraEarned > 0`.
2. **Секція «Заробити більше»** (warm): тихий named-хедер (не eyebrow-кліше) + Пік-години.
3. **Секція «Заповнити вікна»** (cool): named-хедер + Тихий час / Рання бронь / Остання хвилина.
4. **Save** — slate `--btn-primary-bg`, без змін.

### Картка-правило (переписана)
- **Прибрати `border-l-4`** → повна 0.5px межа (`bento-card`) + іконка-чип у семантичному тінті як носій кольору.
- Тогл + розгортання конфіга (дні/години/%) лишаю 1:1.
- **+рядок живого прев'ю** у розгорнутій картці: «приклад: 500 ₴ → 575 ₴», реагує на поточний %. Амбер для надбавки / green для знижки. База 500 ₴ — ілюстративна, чесно лейблиться «приклад».
- **БЕЗ nested cards:** секція = named-хедер-роздільник + плоскі картки під ним (не картка-в-картці).

### PricingUpgradeGate (повний редизайн, founder)
- Усі 3 view (TrialActive / TrialExhausted / ProGate) → перебудувати під мову нового hero/секцій.
- Хекси → токени: `#5C9E7A/#789A99` → `--success`, `#C05B5B` → `--destructive`/`--warning`, `#D4935A` → `--warning`.
- `barColor()` хекс-рампа → токен-рампа.
- TrialActive earned-картка лишає наратив заробітку для Starter (див. рішення нижче).

## Рішення грилу (зафіксовані)

1. **Доказ-цифра дублюється з trial-гейтом.** `TrialActiveView` вже показує «Зароблено {X} ₴». → Hero-цифра **тільки для Pro/Studio**; Starter лишає наратив гейту. Без двох hero стосом.
2. **`dynamic_pricing_extra_earned` рахує лише надбавку** (тригер додає `dynamic_extra_kopecks > 0` тільки для markup). Майстер на самих знижках → 0. → Наявний продукт уже трактує це як trial-метрику «зароблено»; вирівнююсь з існуючою семантикою, hero показую лише коли >0. Нюанс знаю, не роздуваю (як виручка≠прибуток у M-REV-01).
3. **`quietHoursInsight` завжди `null`** (DynamicPricingPage передає null) → `QuietHoursWidget` мертвий. Це дані-інсайт → територія M-REV-05. Не чіпаю.

## Follow-up (founder, 2026-06-28) — 3 доробки в тій самій задачі

**A. Тап-тултіпи на інфо-чіпах (Стекінг / Max -30% / Max +50%).** Було `title=` (лише ховер, мертве на тапі). Чіпи → кнопки `aria-pressed`, тап розкриває пояснення під сіткою з каретом до активного чіпа. Overflow-safe (AnchoredTooltip w-72 вилазив би на правому чіпі).

**B. Врятовані слоти поряд із доходом.** Read-side `getDynamicPricingSavedSlots()` — `confirmed+completed` записи зі знижковим лейблом (`dynamic_pricing_label IS NOT NULL AND dynamic_extra_kopecks = 0`). Рядок результату адаптивний: дохід+слоти / лише дохід / лише слоти. **Закрило діру грилу:** майстер на самих знижках раніше бачив порожній рядок (earned=0), тепер бачить врятовані слоти.

**C. Прев'ю по типу правила, не на кожній картці.** Прибрано з 4 карток → на рівень секцій: одне під «Заробити більше» (пік %), одне під «Заповнити вікна» (найбільша увімкнена знижка). Показ лише коли ≥1 правило секції ON.

**D. Модалка статистики по кожному правилу (founder: «всі метрики»).** Тягне M-REV-05 частково.
- RPC `get_pricing_rule_stats(p_rule_marker)` — **фільтр по `auth.uid()`, без IDOR** (не приймає master_id); матч по підрядку лейбла; `SECURITY DEFINER`+`search_path`; `REVOKE public`/`GRANT authenticated`. Міграція `20260628000003` (MCP+локально).
- Кнопка `BarChart3` у хедері картки = **sibling-button** (3 окремі кнопки: назва/тогл · стата · перемикач — без вкладених, a11y). Відкривається й для вимкнених правил (історія).
- `PricingRuleStatsSheet` (vaul Sheet, дзеркало FlashDealDetailSheet): кількість + ₴ (надбавка) + сер.% (парс із лейбла) + остання дата + 5 останніх записів. Loading/empty стани.

**Чесні межі даних:** знижки лише кількість+% (₴ нема — не додають дохід); pre-feature записи без лейбла; змішаний запис (пік+остання) → у надбавку (не рахуємо двічі).
