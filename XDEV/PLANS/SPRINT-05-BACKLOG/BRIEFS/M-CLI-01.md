## Поточний стан
- Скрін: `SCREENS/M-CLI-01.png` — грід клієнтів, картки різної висоти, «Записати» CTA не на одній лінії.
- Грід: `ClientsPage.tsx:541` — `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-2 gap-3 lg:gap-4`. **НЕ віртуалізований** (віртуалізатор лише для list-view, `count: 0` коли grid). CSS grid → `align-items: stretch` за замовчуванням.
- Картка: `ClientGridCard.tsx` — root `motion.div` `bento-card p-4 flex flex-col gap-3` **без `h-full`**; інфо-секція (`<button>`) без `flex-1`; екшн-бар останнім блоком.

## Ціль (root cause + напрям)
**Root cause:** CSS grid вже робить картки в одному рядку рівними по висоті (stretch). Але всередині картки контент пакується зверху (немає `flex-1`-розпірки), тому при різному вмісті над екшн-баром (умовний `at_risk`-алерт р.135, перенос імені/VIP, наявність `last_service_name`) кнопки «Записати» опиняються на різній вертикалі → візуальний злам.

**Напрям:** фіксована флекс-структура з зонами + притиснутий донизу екшн-бар.
1. Root `motion.div` → `+ h-full` (заповнює розтягнуту grid-клітинку).
2. Інфо-`<button>` → `+ flex-1` (росте, штовхає екшн-бар до низу) → CTA «Записати» завжди на одній лінії в межах рядка.
3. Зони над екшн-баром з консистентним ритмом, щоб і блок «Візитів/Витрачено» вирівнювався: ім'я+статус — стабільна min-height (1↔2 рядки не зсувають аватар), `at_risk`-алерт — рішення за відкритим питанням нижче.
4. `design-taste-frontend` строго в межах Frost (наявні токени `--surface`, `RETENTION_CONFIG`), без нав'язування чужої системи.

## Ризики / що може зламатись
- Режим редагування нотатки (textarea, р.162) розгортає картку — якщо форсити рівну висоту всіх рядків (`grid-auto-rows: 1fr`), редагування роздує ВСІ картки. Тому editing лишається transient (per-row stretch його не чіпає).
- `ClientGridCard` під `React.memo` — структурні зміни не ламають memo (props ті самі).
- Мобілка (`grid-cols-1`) — один стовпець, вирівнювання тривіальне; зміни не нашкодять.
- list-view (віртуалізований) не чіпається.

## Відкриті питання до тебе
1. **Рівна висота — у межах рядка чи весь грід?** За замовчуванням CSS grid рівняє картки **в межах рядка** (рекомендовано: природно, без зайвого простору). Альтернатива — `grid-auto-rows: 1fr` рівняє ВСІ картки під найвищу (ризик: багато порожнечі + редагування роздуває все). Який варіант?
2. **`at_risk`-алерт «Пора нагадати про себе»** — лишити умовним (показується лише для at_risk; екшн-бар все одно вирівняний завдяки flex-1) чи зарезервувати слот на всіх картках (ідеально рівний внутрішній ритм, але порожній простір на не-at_risk)?
