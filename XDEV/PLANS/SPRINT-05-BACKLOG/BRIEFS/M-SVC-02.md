## Дизайн-напрям

«Топ-картка маркетплейсу» = візуал-форвард картка-лістинг (як storefront-плитка), але це лишається **management-в'ю майстра** — усі контролі зберігаються, просто переодягнені. НЕ клієнтська картка (це M-SVC-03).

Доступні дані: `name, icon_name, category, price, duration, popular, active, description?, imageUrl?`.

**Критичний момент — fallback без фото:** більшість послуг без `imageUrl`. Image-зона має красивий стан за замовчуванням — тонований градієнт (Frost-акцент) + великий `ServiceIcon` по центру, не «битий» плейсхолдер. Фото, якщо є, перекриває.

## Ризики

- Вертикальна плитка з фото-зоною подвоює висоту → довший скрол для майстрів з багатьма послугами. Density vs vitrine — компроміс.
- Більшість карток підуть на icon-fallback → якість fallback вирішує весь вигляд.
- DnD: drag-handle має лишитись досяжним і в новому лейауті; перетягування плиток у 2-col гріді вже працює — не ламати.
- Touch ≥44px на всіх діях (toggle вже 44, edit/delete size-11=44).
- Неактивна послуга: лишити `opacity-55` чи інша візуальна мова.

## Рішення founder (QA 3/3)

### План реалізації
- `ServiceCard.tsx`: переверстати на flex-row — ліворуч квадрат `aspect-square` ~110px (фото `object-cover` АБО Frost-градієнт-тінт + великий `ServiceIcon`), drag-handle оверлеєм на квадраті (hover); праворуч колонка: назва+popular → опис clamp → мета-рядок (категорія-піл + тривалість) → ціна. Footer-рядок дій лишається знизу на всю ширину картки (під квадратом+контентом) АБО у правій колонці — визначити версткою щоб 44px не ламались.
- `ServicesPage.tsx`: `LoadingState` skeleton підігнати під новий розмір картки (вищий, квадрат зліва). Грід `md:grid-cols-2` лишити.
- Неактивна: лишити `opacity-55`.
- Без нових запитів/полів. Без клієнтського режиму (M-SVC-03).

### Підсумок реалізації (3 ітерації founder)
1. Стартував гібрид (квадрат+контент) → founder редирект на горизонталь з фото full-height → фінально **перший варіант: вертикальна плитка фото-зверху**.
2. Founder доповнив скоуп ad-hoc: **другий режим перегляду — список**. Реалізовано перемикач сітка/список у сайдбарі + localStorage persistence. ServiceCard отримав `view` проп, спільні `editDelete`+`toggle` блоки.
3. Скарга: у списку назви різались (ціна забирала ширину). Fix: правий стовпчик ціна-над-діями → назва на всю ширину, `line-clamp-2` в обох режимах = повні назви.

### Root cause «назви ріжуться»
`line-clamp-1` + ціна як inline-сусід контенту (flex-1 min-w-0 стискався під ціну+дії). Рішення структурне: винести ціну у вертикальний правий стовпчик разом з діями, звільнивши горизонталь для імені.

### KEY
- Marketplace-вигляд у management-в'ю = фото-зона (з якісним icon-fallback) + акцент ціни, але контролі (DnD/toggle/hide) лишаються видимими, не ховаються під hover (touch-екран майстра — головний).
- Два режими через `view` проп + спільні блоки дій = нуль дублювання логіки edit/delete/toggle.
- Повні назви: ціна не має бути inline-сусідом імені в горизонтальному рядку; винось її в окремий стовпчик, інакше ім'я стискається.
