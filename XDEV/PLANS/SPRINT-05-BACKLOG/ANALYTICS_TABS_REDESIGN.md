## 0. Спільна основа (читати перед будь-яким табом)

### Закон редизайну (Принцип темного блоку)
1. **Проектуй з концепту, з нуля. НЕ ретрофіть** наявний віджет косметикою.
2. **Асиметрична ієрархія + драма в КОЖНІЙ секції:** один **герой** (домінанта) + диференційований решток. (= PRODUCT.md anti-ref #1: унікальна ієрархія, бан однакових bento.)
3. **Маркер провалу = рівномірність** (N рівних карток/барів) → переробити.
4. **Рендер локально власними очима ДО показу founder** (Playwright headless + мок-прев'ю-роут поза auth).
5. «Сміливо» ≠ «темно». Драма можлива на світлому: типографіка, hairline-структура, домінантні числа.

### Спільні компоненти для переюзу (вже існують після Огляду)
| Компонент | Призначення |
|-----------|-------------|
| `sections/OverviewTab.tsx` → `SectionHeading` | Editorial-заголовок секції: serif h3 + hairline-правило + опційний action-слот. **Юзати в кожному табі.** |
| `sections/OverviewDetailSheet.tsx` (`OverviewDetail` тип) | Адаптивний Sheet деталей (vaul mobile / dialog desktop). Payload: `hero`, `rows[]`, `note`, `cta`. **Кожен клікабельний елемент → сюди.** |
| `sections/FeaturedServices/Products/Clients.tsx` | Зразок патерну «герой + ранг-список». Копіювати структуру, не вміст. |
| `charts/RevenueLineChart.tsx` | Зразок recharts-чарта (ComposedChart + градієнт + кастомний тултіп). **`isAnimationActive={false}` на Area — інакше зникає в headless/фон-табі.** |
| `primitives/BentoCell.tsx` | Картка-обгортка (min-h прибрано — росте за контентом). |
| `ui/Sheet.tsx` | База адаптивного Sheet. |

### Дизайн-мова (з Огляду)
- **Числа:** `metric-value` (tabular-nums) + slate-акцент. Заголовки секцій/героїв — `heading-serif` (Cormorant).
- **Кольори:** Frost-токени тільки. Текст `text-foreground` / `text-text-sub` (#475569, 5.88:1). **Заборонено** `text-muted-foreground/60` на світлому (2.76:1 — провал a11y).
- **Hero-блок** (як обкладинка Огляду): `--hero-card-bg` (#0F172A slate) + `--accent-on` (cream). Контраст білих alpha на slate: `/55`=6.09 ✓, `/45`=4.46 ✗.
- **Ранги:** slate-чіп (#1 з акцентом), не грайливі кольорові кружечки.
- **Сітка:** десктоп `grid-cols-12` асиметрія; мобільний — одноколонка.
- **a11y:** графіка 3:1, текст 4.5:1 — перевіряти `mcp__a11y`. Графіка amber на periwinkle ~3.9 (3:1 ✓).
- **Pro-gate:** не-Pro таб → не порожнеча, а цінність-обіцянка (як `AnalyticsActivation`).

### 🔴 ФЕЙКИ ДЛЯ ВИПРАВЛЕННЯ (виявлено при документуванні — НЕ тиражувати!)
1. **`VacationTab` «Рятувальник відпустки»:** кнопка «Оптимізувати розклад» лише показує тост, нічого не робить. «Врятуйте ₴X» = `lost*0.4` вигадка. → Переписати на чесне (реальна дія або прибрати кнопку, лишити аналіз втрати).
2. **`FinancesTab` / `StockTab`:** при відсутності даних рендерять **захардкоджені dummy-числа** (`displayFin`/`displayItems`) під блюром+оверлеєм. Це teaser, але це фейк-числа. → Замінити на skeleton-силует без конкретних чисел (як у Принципі: нуль фейк-даних).
3. Аналог старого `SmartPricingOptimizer` (вже виправлено в Огляді — взяти за зразок чесного нуджа).

## 1. Таб «Зростання» (`growth`) — Pro

### Логіка
- Дані: `useAnalyticsExtras` (scope `all` → `dynamic_pricing_uplift`, `ltv_concentration`, `service_pairing`, `cohort_matrix`) + `useAnalyticsMarketing` (flash/broadcasts/loyalty/referrals).
- Рендериться `BentoSecondary` (smart-pricing uplift, flash-deals, broadcasts, LTV-концентрація Парето, winback-кандидати, пари послуг) + `GrowthLists` (лояльність + реферали) + `CohortHeatmap` (когорти повернення).

### UX
- Питання: «що рухає ріст і кого повертати». Найдієвіший таб — тут реальні CTA (winback, pricing).
- Дія: тап по winback-кандидату → профіль клієнта; пари послуг → інсайт для апсейлу.

### UI-редизайн (концепт: «двигуни росту»)
- **Герой:** найсильніший важіль періоду (напр. «Smart Pricing +N₴» або «Топ-20% = X% доходу») великим serif-блоком зверху, з дією. Не рівний ряд карток.
- **Решток:** LTV-Парето як featured-візуалізація (розподіл) + winback-список (герой+ранг) + пари послуг компактно.
- Когорти — повноширинна теплова стрічка внизу.
- Клік: кожен growth-важіль → `OverviewDetailSheet` (розклад + дія) або профіль клієнта.

## 2. Таб «Поведінка» (`behavior`) — Pro

### Логіка
- `HeatmapGrid` (`extras.occupancy_heatmap` — завантаженість год×день) + 3 під-таби: `LeadTimeTab`, `NoShowTab`, `VacationTab`.
- LeadTime: `useLeadTimeDistribution` (5 бакетів часу до запису + середній). NoShow: `useNoShowMetrics` (неявки/скасування % + журнал). Vacation: `useVacationImpact` (втрачена вигода = сер.день × днів відпустки).

### UX
- Питання: «коли я завантажений, чому втрачаю клієнтів, скільки коштують вихідні».
- Зараз 4 окремі блоки стопкою — найдовший і найрозфокусованіший таб.

### UI-редизайн (концепт: «ритм бізнесу»)
- **Герой:** теплова карта завантаження як головний візуал (коли працюю на піку) — велика, не втиснута.
- **Решток:** LeadTime-розподіл + No-Show% + Vacation-втрата як диференційовані врізки, не рівні картки.
- **No-Show журнал:** герой = найбільша втрата/частий неявник + список.
- **🔴 Vacation:** прибрати фейк «Оптимізувати розклад». Лишити чесний аналіз втрати + реальний лінк на налаштування вихідних.
- Клік: метрика → пояснення формули (`OverviewDetailSheet.note`); інцидент → профіль клієнта.

## 3. Таб «Відгуки» (`reviews`)

### Логіка
- `useReviewsMetrics` (NPS −100..+100, середній бал, розподіл 5★→1★, останні відгуки). Доступний усім (не Pro-gated).

### UX
- Питання: «наскільки мене люблять і що пишуть». Дублює частину сторінки Reviews (M-REVW-01 вже редизайнено — взяти її мову!).

### UI-редизайн (концепт: «репутація»)
- **Герой:** середній бал великим serif + зірки + NPS-чіп (як hero-зріз у M-REVW-01 `ReviewsPage` — переюзати підхід).
- **Решток:** розподіл-як-фільтр (гістограма-кнопки, як M-REVW-01) + стрічка останніх відгуків.
- Клік: відгук → `ReviewDetailSheet` (вже існує в reviews-модулі) або `OverviewDetailSheet`.
- ⚠️ Узгодити з уже-редизайненою `ReviewsPage` — не розходитись у мові.

## 4. Таб «Джерела» (`source`)

### Логіка
- `useSourceAttribution` (звідки прийшли записи) → `ChannelDonut`. Найпростіший таб (один графік).

### UX
- Питання: «який канал приводить клієнтів». Зараз — самотній donut у картці, бідно.

### UI-редизайн (концепт: «канали»)
- **Герой:** найсильніший канал великим числом + часткою («Instagram — 64% записів»), donut поряд як підтримка.
- **Решток:** ранг-список каналів (герой+решта) з частками і трендом, не лише donut.
- Клік: канал → деталі (скільки записів, виручка, конверсія) через `OverviewDetailSheet`.
- Можливість збагатити: виручка per-канал (не лише кількість) — перевірити, чи є в хуку.

## 5. Таб «Фінанси» (`finances`) — Pro

### Логіка
- `useAnalyticsExtras` scope `finances` → виручка послуг/товарів, собівартість розхідників, знижки, операційні витрати, чистий прибуток, маржинальність per-послуга. `WaterfallChart` (6 барів). Алерт низької маржі (<40%) з лінком на редагування ціни.

### UX
- Питання: «скільки реально заробляю після витрат і де втрачаю маржу». Найцінніший Pro-таб для рішень.

### UI-редизайн (концепт: «P&L звіт»)
- **Герой:** чистий прибуток великим serif + Δ + waterfall як головний візуал (виручка → мінус витрати → прибуток).
- **Решток:** маржинальність-список = герой (найнижча маржа = найбільший ризик) + ранг; алерт як дія.
- **🔴 Прибрати dummy-числа** при empty — skeleton-силует без конкретики.
- Клік: послуга → маржа-розбивка (виручка/собівартість/% + рекомендація) через `OverviewDetailSheet`.

---

## 6. Таб «Склад» (`stock`) — Pro

### Логіка
- `useAnalyticsExtras` scope `stock` → прогноз закінчення розхідників (`predicted_days_left` на основі 14-дн темпу). Світлофор (критичні ≤3дн / увага ≤7дн / норма). Генератор списку покупок (копіювання).

### UX
- Питання: «що скоро закінчиться і що купити». Дієвий — список покупок реальний.

### UI-редизайн (концепт: «склад під контролем»)
- **Герой:** найкритичніший дефіцит великим блоком («Фарба — 2 дні!») з дією «купити», не 3 рівні світлофор-картки.
- **Решток:** ранг-список за терміновістю (герой+решта) + кнопка списку покупок.
- **🔴 Прибрати dummy-числа** при empty.
- Клік: товар → деталі (запас/темп/прогноз/собівартість) + лінк на поповнення через `OverviewDetailSheet`.
