# Звіт про аудит: Етап 2 (Рівень бази даних та міграції)

Ми провели аудит рівня бази даних, що охоплює всі 139+ міграцій (знаходяться в `supabase/migrations/`), таблиці, обмеження цілісності, тригери та налаштування політик безпеки Row Level Security (RLS).

## 1. Аудит політик RLS
Row Level Security увімкнено для всіх таблиць бази даних. Перевірено ключові політики безпеки:
- **`bookings`**: Забороняє авторизованим користувачам створювати записи від імені інших осіб (`client_id = auth.uid() OR client_id IS NULL` для гостьових записів).
- **`booking_services` та `booking_products`**: Обмежує доступ на читання тільки власнику запису (`master_id = auth.uid() OR client_id = auth.uid()`).
- **`billing_events` та `master_subscriptions`**: Повністю заблоковані для будь-яких користувацьких токенів авторизації (`FOR ALL USING (false)`). Це гарантує, що операції з білінгом та токенами карток можуть виконуватися виключно через `service_role` (серверна частина Monobank).
- **`broadcasts` та `broadcast_recipients`**: Доступ надається на основі перевірки приналежності розсилки профілю майстра.
- **`phone_discounts` та `broadcast_links`**: Доступні для публічного читання (необхідно для пошуку знижок за номером телефону під час гостьового запису та для роботи редиректів коротких лінків), але редагування дозволене лише з роллю `service_role`.

## 2. Тригери та цілісність даних
- **Синхронізація здоров'я клієнтів**: Тригер `trg_sync_client_health` у таблиці `profiles` стежить за оновленнями полів `health_notes` та `medical_notes` і автоматично синхронізує їх з усіма зв'язками в `client_master_relations`.
- **М'яке видалення (Soft Deletes)**: Реалізовано для таблиць послуг (`services`) та товарів (`products`) шляхом встановлення прапорця `is_archived: true` / `is_active: false`. Це дозволяє уникнути порушення зв'язків (Foreign Keys) у минулих записах клієнтів.

## 3. Безпечні RPC-функції для конкурентних запитів
Система використовує збережені процедури (RPC) для запобігання race conditions:
- **`claim_phone_discount`**: Захоплює рядок знижки за допомогою `FOR UPDATE SKIP LOCKED`, запобігаючи подвійному списанню знижки при одночасному записі.
- **`get_master_clients`**: Агрегує статистику візитів, витрат та статус утримання (retention) клієнтів майстра.
- **`check_and_log_sms_attempt`**: Використовує advisory lock для атомарного обмеження частоти запитів SMS OTP.
