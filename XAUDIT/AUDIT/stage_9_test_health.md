## 2. Виявлені та виправлені баги у тестах
Під час першого запуску тестів було виявлено та усунено дві помилки:
1. **Відсутність імпорту в `dynamicPricing.test.ts`**:
   - *Проблема*: Тест використовував глобальні методи `describe`, `it` та `expect` без імпорту, що викликало `ReferenceError` за відсутності глобальних налаштувань у конфігурації.
   - *Фікс*: Додано `import { describe, it, expect } from 'vitest';` на початку файлу.
2. **Некоректний мок клієнта Supabase у `NotificationOrchestrator.test.ts`**:
   - *Проблема*: Мок методу `mockQuery.eq.mockResolvedValueOnce(...)` перехоплював перший виклик `.eq(...)` у ланцюжку до таблиці `profiles`, замість третього до `push_subscriptions`. Через це ланцюжок повертав проміс без методу `.maybeSingle()`, викликаючи збій тесту. Також був відсутній мок для `escHtml` з `@/lib/telegram`.
   - *Фікс*: Переписано мок на базі маршрутизації за назвою таблиці (`profiles`, `master_profiles`, `push_subscriptions`, `notifications`). Кожен ланцюжок тепер отримує свій ізольований та передбачуваний результат. Також додано заглушку для `escHtml`.

## 3. Стан E2E та Playwright тестів
- **Проблема конфігурації**: Vitest за замовчуванням намагався сканувати та парсити файли Playwright E2E специфікацій (`e2e/tests/**/*.spec.ts`), що викликало помилки через відсутність середовища Playwright.
- **Рекомендація**: Для запуску юніт-тестів слід чітко вказувати цільову папку (`npx vitest run src`), або додати файл конфігурації `vitest.config.ts`, де виключити папку `e2e/` зі списку сканування:
  ```typescript
  import { defineConfig } from 'vitest/config';
  export default defineConfig({
    test: {
      exclude: ['e2e/**/*', 'node_modules/**/*'],
    },
  });
  ```
