# Звіт про аудит: Етап 5 (Система сповіщень та черга відправки)

Ми провели аудит архітектури сповіщень та перевірили відповідність правилам каскадної доставки, лімітування SMS та підтримки глибоких посилань (Deep Linking).

## 1. Каскадна модель доставки (Notification Cascade)
- **Файл**: `src/lib/notifications/NotificationOrchestrator.ts`.
- **Логіка роботи**:
  1. **Перший шар (In-App + Web Push)**: Запускаються паралельно. Якщо Web Push успішно доставлено хоча б на один активний пристрій (`pushDelivered: true`), каскад завершується. Неактивні підписки автоматично видаляються з бази даних (`push_subscriptions`).
  2. **Другий шар (Telegram)**: Якщо Push не доставлено (наприклад, немає підписки або помилка доставки) та у отримувача є прив'язаний `telegram_chat_id`, сповіщення надсилається у Telegram.
  3. **Третій шар (SMS-fallback через TurboSMS)**: SMS надсилається **тільки** у разі, якщо:
     - Жоден безкоштовний канал (Push або Telegram) не доставив повідомлення.
     - Подія має статус критичної (`isCritical: true`).
     - Наявний номер телефону отримувача.

## 2. Карта подій та критичність сповіщень
- **Файл**: `src/lib/notifications/constants/notifMap.ts`.
- **Класифікація подій**:
  - **Критичні події** (надсилають SMS у крайньому разі):
    - `booking_created` (Створення запису)
    - `booking_confirmed` (Підтвердження запису)
    - `booking_cancelled` (Скасування візиту)
    - `booking_rescheduled` (Зміна часу майстром)
    - `reminder_2h` (Нагадування за 2 години до візиту)
    - `subscription_failed` (Невдала спроба списання оплати підписки)
  - **Некритичні події** (SMS повністю заблоковані):
    - `booking_completed` (Прохання залишити відгук після візиту)
    - `reminder_24h` / `reminder_30m` (Планові нагадування)
    - `unhandled_booking` (Нагадування майстру про завершення старих записів)
    - `new_review` (Сповіщення майстру про новий відгук)
    - `rebooking_reminder` (Нагадування клієнту записатися знову через деякий час)
    - `portfolio_consent_request` (Запит згоди клієнта на фото в портфоліо)
    - `stock_alert` (Попередження про критичний залишок товару на складі)
    - `subscription_paid` / `subscription_expiring` / `subscription_downgraded` (Статуси білінгу)

## 3. Якість реалізації (WOW-стандарти)
- **Deep Linking**: Усі Web Push та Telegram сповіщення мають посилання на конкретну сутність (наприклад, `/my/bookings?bookingId=...` для записів, `/dashboard/billing` для підписки, `/dashboard/products` для замовлень та товарів).
- **Telegram Inline Buttons**: Для кожної події Telegram формується блок кнопок (`replyMarkup` з `inline_keyboard`) замість звичайних текстових лінків, що робить взаємодію інтерактивною та зручною.
- **Екранування**: Всі змінні, введені користувачем, екрануються функцією `escHtml()` перед відправкою у Telegram (режим `HTML parse_mode`), що повністю виключає XSS або збої рендерингу через спецсимволи (`<`, `>`, `&`).
